# Можно ли прореживать сигнал?
## Простой отчёт — для тех кто не хочет формул

> **Короткий ответ: ДА, можно. И даже нужно. Читай дальше почему.**

---

## Про что вообще этот эксперимент?

Представь: тебе нужно понять, **тихо или громко** играет музыка в соседней комнате.
У тебя есть 1.3 миллиона «нот» (сигнальных точек), и нужно принять решение быстро.

Вопрос: нужно ли слушать **все** 1.3 миллиона нот, или можно слушать **каждую 635-ю** —
и всё равно понять, тихо там или громко?

Мы проверили это математически и экспериментально. Вот что вышло.

---

## Что такое прореживание (decimation)?

```
Исходный сигнал:  ○○○○○○○○○○○○○○○○○○○○○○○○  (1 300 000 точек)
                  │ │ │ │ │ │ │ │ │ │ │ │
После прореживания берём каждую 635-ю:
Прорежённый:      ○         ○         ○      (≈2 050 точек)
```

Мы не просто выбрасываем данные — мы **равномерно захватываем весь временной отрезок**,
но реже. Как смотреть фильм через 1 кадр из 25-ти: действие видно, детали чуть хуже.

---

## Что мы измеряли?

Мы брали сигналы с разной «громкостью» (SNR = отношение сигнал/шум):

| Метка | Что это значит |
|:-----:|:--------------|
| SNR = 5 dB  | Сигнал еле слышен — на 5 dB громче шума |
| SNR = 20 dB | Средний сигнал |
| SNR = 50 dB | Очень мощный, шума почти нет |

Для каждого сигнала мы считали **насколько точно** определяется его «громкость»
при разной степени прореживания.

---

## Главная находка №1 — Прореживание работает!

При прореживании до **2048 точек** (из 1.3 миллиона):

```
Сигнал 5 dB   → оценка 35.5 dB   ← правильно: "высокий SNR"
Сигнал 20 dB  → оценка 50.4 dB   ← правильно: "высокий SNR"
Сигнал 50 dB  → оценка 80.2 dB   ← правильно: "очень высокий SNR"
```

Пороги классификации (Low / Mid / High) **откалиброваны** именно под 2048 точки.
Система правильно распознаёт ветку сигнала в 97.9% случаев — **так же как без прореживания**.

---

## Что значит «оценка 35.5 dB»? Почему не 5 dB?

Это самый важный вопрос для понимания всего отчёта.

**Оценка 35.5 dB — это НЕ входной SNR.** Это то, что увидел детектор (CA-CFAR) в спектре FFT:
отношение **высоты главного пика** к **среднему уровню шума рядом с ним**.

### Картинка: что видит FFT

```
Мощность в бинах FFT после прореживания до 2048 точек:

|X[k]|²
  ▲
  │          ███   ← пик сигнала
  │         █████    Насколько пик выше соседей?
  │        ███████   → вот это и есть «оценка»
  │                   = 35.5 dB выше среднего шума
  │  ▂▂▂▂▂▂       ▂▂▂▂▂▂  ← средний шум (reference bins)
  │▂▂                   ▂▂
  └────────────────────────────► бин (частота)
           │   guard=5   │
           └──── ref=16 ──┘
              (эти бины берём
               как образец шума)

  CFAR SNR = 10·log₁₀( высота пика / средний шум ) = 35.5 dB
```

### Откуда берётся «лишние» 30 dB?

Входной сигнал тихий — всего 5 dB над шумом (в одном отсчёте).
Но FFT из 2048 точек работает как **2048 слушателей, которые слушают одновременно**:

```
Сигнал (один тон) складывается СОГЛАСОВАННО (когерентно):
   все 2048 слышат один и тот же тон → суммируют в унисон
   пик растёт в 2048 раз по мощности  = +33 dB

Шум складывается ВРАЗНОБОЙ (некогерентно):
   у каждого свой случайный шум → при суммировании частично гасят друг друга
   шум растёт только в √2048 ≈ 45 раз по мощности = +16.6 dB
```

Итог:

```
                 Пик    растёт на +33 dB
                 Шум    растёт на +16.6 dB
                 ─────────────────────────
                 Разница = +33 − 16.6 ≈ +16.6 dB ... (это и есть половина SNR-gain!)

   Точнее для Hann-окна (с поправкой на форму окна):
   Processing gain = 10·log₁₀(2048) − 1.76 = 33.1 − 1.76 = +31.4 dB
```

Поэтому:

```
   Входной SNR  +  Processing gain  =  Что видит CFAR
        5 dB    +      31.4 dB      =    36.4 dB  ≈  35.5 dB (измерено ✓)
       20 dB    +      31.4 dB      =    51.4 dB  ≈  50.4 dB (измерено ✓)
       50 dB    +      31.4 dB      =    81.4 dB  ≈  80.2 dB (измерено ✓)
```

### Как связаны пороги классификации с этим числом?

Пороги Low/Mid/High настроены **не на входной SNR, а на выход CFAR при N_fft=2048**:

```
  CFAR выход < 15 dB  →  Low   (чистый шум, SNR_входной < −16 dB)
  15 ≤ CFAR < 30 dB   →  Mid   (очень слабый сигнал)
  CFAR ≥ 30 dB        →  High  (сигнал есть, SNR_входной > −1 dB)

  Наши тест-сигналы [5..50 dB входного] → CFAR [35..80 dB] → все попадают в HIGH ✓
```

Пороги **уже включают** в себя processing gain. Поэтому менять N_fft = менять пороги.
Именно поэтому нельзя просто так взять другой N_fft без перекалибровки порогов.

> **Вывод:** «оценка 35.5 dB» — это не «сигнал 35.5 dB громче шума в исходном сигнале»,
> а «пик в спектре FFT в 35.5 dB выше среднего шума в соседних бинах». FFT выступает
> как усилитель с коэффициентом +31 dB, который одинаково применяется ко всем
> входным SNR. Пороги калиброваны под этот усилитель — поэтому всё работает.

## Главная находка №2 — Больше точек не помогает!

Это контринтуитивно, но важно.

Мы взяли **все 1.3 миллиона точек** (без прореживания, максимальное FFT) и посмотрели:

```
Сигнал 5 dB   → оценка 54.96 dB
Сигнал 10 dB  → оценка 55.19 dB
Сигнал 50 dB  → оценка 55.28 dB
```

**Все три дают примерно одно и то же! (~55 dB)**

Почему? Когда данных очень много, FFT-спектр становится очень «острым».
Боковые «отражения» основного пика начинают мешать измерению шума.
Это как пытаться расслышать тихий звук стоя рядом с громким — отражения от стен мешают.

**Вывод:** использование всех 1.3M точек **не даёт** никакого преимущества
и не улучшает классификацию.

## Главная находка №3 — Формула работает идеально

Для прорежённого сигнала (≤8192 точек после прореживания) выполняется простая формула:

```
Что измеряем = Входной SNR + Усиление от FFT

Усиление от FFT:
  2048 точек → +31.4 dB
  4096 точек → +34.4 dB
  8192 точек → +37.4 dB
```

Пример: сигнал 5 dB, прореживание до 2048 точек:
```
Ожидаем: 5 + 31.4 = 36.4 dB
Измерили:           35.5 dB  ✅ (расхождение < 1 dB)
```

## Почему это работает без потерь?

Представь что ты слушаешь голос человека, который говорит долго и монотонно
(как наш CW-сигнал). Если ты слышишь каждое слово — хорошо.
Если слышишь каждое 635-е слово — тоже понимаешь что он говорит и с какой громкостью.

Потому что:
1. Сигнал **стационарный** (не меняется во времени)
2. Шум тоже **равномерный** (не «собирается» в определённых точках)
3. Мы берём точки **равномерно** по всему времени наблюдения

```
Часть А: 1.3M отсчётов → прореживаем до [1024, 2048, 4096, ..., 1M]
         Смотрим как меняется результат при каждом варианте.
         ВЫВОД: при 2048 результат стабилен, при 1M — насыщение.

Часть Б: Уменьшаем число ВХОДНЫХ отсчётов [1.3M → 2.5K], 
         но всегда прореживаем до 2048.
         ВЫВОД: результат почти не меняется! (входная длина не важна)

Часть В: Уменьшаем входные отсчёты И не прореживаем (берём все).
         ВЫВОД: при больших данных — насыщение; при малых — теряем точность.
```

#### Панель A (верхний левый) — «Что показывает FFT-детектор при разном прореживании?»

```
Ось X (горизонталь): log₂(N_fft) — сколько точек использует FFT
                     10 = 1024 точки,  11 = 2048,  20 = 1M,  21 = 2M (baseline)
Ось Y (вертикаль):  CFAR SNR (дБ) — что видит детектор в спектре
```

На графике нарисованы **10 цветных линий** — по одной на каждый входной SNR от 5 до 50 dB.
Цвет линии идёт от фиолетового (5 dB, самый слабый) до жёлтого (50 dB, самый мощный).

**Что видно:**

- Все линии идут **параллельно снизу вверх** — это главный признак того, что прореживание
  работает честно: каждый входной SNR получает одинаковый выигрыш от FFT.
- Пунктирные линии того же цвета — это теоретическое предсказание. Они совпадают
  с измерениями при N_fft ≤ 65536, а при больших N_fft расходятся (насыщение).
- **Звёздочки** на правом краю (x=21) — это baseline (все 1.3M точек без прореживания).
  Все звёздочки кучкуются около 55 dB **независимо от цвета (входного SNR)** — это
  насыщение по боковым лепесткам.
- Горизонтальные пунктирные линии: красная = 15 dB (порог Low→Mid),
  оранжевая = 30 dB (порог Mid→High).
- Вертикальная синяя пунктирная линия — рекомендуемый target_n_fft=2048.

**Главный вывод панели:** при N_fft=2048 все 10 тест-сигналов оказываются
**выше 30 dB** (зона High) — классификатор работает правильно. При уменьшении
N_fft до 1024 слабые сигналы (5 dB) снижаются до ~33 dB — всё ещё High, но
запас уменьшается.

---

#### Панель B (верхний правый) — «На сколько дБ теряем при прореживании?»

```
Ось X: log₂(N_fft) — размер FFT после прореживания
Ось Y: δ (дБ) — разница между прорежённым и baseline (отрицательные значения)
```

Здесь нарисованы те же 10 цветных линий, но теперь вычтен baseline каждой линии.

**Что видно:**

- Все 10 цветных линий **практически совпадают** при малых N_fft (до 65536).
  Это означает: потеря в дБ **одинакова** для всех входных SNR. Слабый и мощный
  сигнал теряют ровно столько же. Это подтверждает формулу: δ = −10·log₁₀(D).
- **Белая пунктирная линия** — теория δ = −10·log₁₀(D). При малых N_fft все
  измеренные линии идут вдоль неё точно.
- При больших N_fft (> 65536) линии расходятся — потому что вступает насыщение
  и линейная модель перестаёт работать.
- **Аннотация** на графике показывает точку N_fft=2048: δ ≈ −30 dB, D ≈ 635.
  Это наш рабочий режим.

**Главный вывод панели:** прореживание в 635 раз даёт −30 dB потерю детектора —
но это не потеря классификации! Пороги откалиброваны с учётом этих −30 dB.

---

#### Панель C (нижний левый) — «Важна ли длина входного потока?»

```
Ось X: log₂(N_input) — сколько входных отсчётов мы берём (до прореживания)
Ось Y: CFAR SNR (дБ)
Условие: target_n_fft=2048 фиксирован всегда
```

Мы берём разное количество входных отсчётов (от 1.3M до ~2.5K),
но **всегда прореживаем до N_fft≈2048**.

**Что видно:**

- Для слабых сигналов (фиолетовые линии, 5–15 dB): CFAR SNR остаётся
  практически **горизонтальным** — около 35–45 dB вне зависимости от входной длины.
  Это потрясающий результат: можно взять в 512 раз меньше данных и получить тот же ответ!
- Для сильных сигналов (жёлтые, 40–50 dB): наблюдается небольшой разброс (±5 dB).
  Причина: при разных шагах прореживания сигнальный тон попадает в разные дробные части бина FFT
  (scalloping effect). Но оценка всё равно остаётся в зоне High.
- Пунктирные линии — теория: при target=2048 должна быть горизонтальная прямая.
  Это видно для слабых SNR.

**Главный вывод панели:** длина входного потока **не имеет значения** при
target_n_fft=2048 — результат стабилен начиная от 4096 входных точек.

#### Панель D (нижний правый) — «Что выгоднее: прореживать или брать меньше данных?»

```
Ось X: log₂(N_input) — длина входного отрезка
Ось Y: CFAR SNR (дБ)
Сплошные линии: target=2048 (прореживаем)
Штриховые линии: step=1 (все точки, N_fft = N_input)
Показаны 4 SNR уровня: 10, 20, 30, 40 dB
```

Сравнение двух стратегий на одном графике.

**Что видно:**

- Сплошные линии (target=2048) — практически горизонтальные: CFAR ≈ const
  для любой входной длины. Это стабильная стратегия.
- Штриховые линии (step=1) — растут слева направо: чем больше данных берём,
  тем выше CFAR SNR. Но при больших N_input они «упираются» в насыщение (~55 dB).
- При малых N_input (<8192) штриховые линии ниже сплошных — то есть **прореживание
  до 2048 лучше**, чем брать только первые 4096 точек без прореживания.
- При больших N_input штриховые линии выше — но обе стратегии уже дают High.

**Главный вывод панели:** при большом потоке данных (1.3M) прореживать до 2048 —
это **лучшая стратегия**: быстро, стабильно, точно.

### Файл 2: `decimation_delta_collapse.png` — «схлопывание» дельты (2 панели)

Это увеличенная версия двух самых важных наблюдений эксперимента.

---

#### Панель 1 (левая) — «Collapse: все SNR дают одну и ту же потерю»

```
Ось X: log₂(N_fft_actual) — размер FFT
Ось Y: δ (дБ) — потеря от baseline
10 цветных линий (фиолетовый=5dB → жёлтый=50dB)
1 белая пунктирная линия — теория δ = −10·log₁₀(D)
```

Это самый красивый результат эксперимента.

**Что видно:**

- Все 10 цветных линий идут **бок о бок** — они почти неотличимы друг от друга
  в диапазоне N_fft = 1024..65536. Это «коллапс»: потеря не зависит от входного SNR.
- Белая пунктирная линия — теоретическое предсказание −10·log₁₀(D).
  Все цветные линии идут точно по ней. Теория и эксперимент совпадают идеально.
- **Аннотация** со стрелкой указывает на точку N_fft=2048: δ = −30.1 dB, D≈635.
  Именно столько «теряем» при нашем рабочем прореживании.
- При N_fft > 131072 линии начинают расходиться — входим в нелинейную зону насыщения.
- Вертикальная синяя линия отмечает N_fft=2048 — рабочую точку системы.

**Читать этот график нужно так:** «Все цветные линии сошлись в одну — значит,
прореживание справедливо для всех сигналов. Сильный и слабый сигнал теряют
ровно одинаково (30 dB), и ровно столько заложено в пороги».

---

#### Панель 2 (правая) — «Абсолютные значения CFAR SNR — параллельные линии»

```
Ось X: log₂(N_fft_actual)
Ось Y: абсолютный CFAR SNR (дБ), без вычитания baseline
10 цветных сплошных линий — измерения
10 цветных пунктирных линий — теория
```

**Что видно:**

- Все 10 линий идут **параллельно** в диапазоне N_fft = 1024..65536.
  Вертикальное расстояние между соседними линиями = 5 dB (разница входных SNR).
  Это доказывает, что CFAR корректно ранжирует сигналы по мощности.
- Пунктирные теоретические линии совпадают с измерениями в линейной зоне.
- При N_fft > 65536 линии перестают быть параллельными — все сходятся к ~55 dB.
  Это зона насыщения: детектор «ослеп» из-за боковых лепестков Hann.
- Горизонтальная белая пунктирная линия у нуля помогает читать значения.

**Читать этот график нужно так:** «Параллельные линии = честная оценка.
Детектор всегда правильно отличает сигнал 5 dB от сигнала 50 dB.
При насыщении (правая часть) — это различие пропадает, все линии сливаются в 55 dB».
