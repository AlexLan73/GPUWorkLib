## Цель

Создать матричный бенчмарк FFT на ROCm: таблица времени вычисления для различных комбинаций (лучи × размер FFT).

## Параметры (подтверждены Алексом)

| Параметр | Значение | Описание |
|----------|----------|----------|
| **Столбцы (nFFT)** | 2^4 ... 2^16 = 16...65536 | 13 значений |
| **Строки (лучи)** | 20, 40, 60, ... 400 (шаг 20) | 20 значений |
| **Итого комбинаций** | 13 × 20 = **260** | |
| **N warmup** | **5** | Прогрев GPU перед замерами |
| **N runs** | **10** | Замеров для статистики (avg) |
| **output_mode** | **COMPLEX** | Чистый FFT без MagPhase ✅ |
| **Контрольная точка** | **320×1024** | В НАЧАЛЕ и в КОНЦЕ матрицы |

### Память (проверка)

Максимальная комбинация: 400 лучей × 65536 точек × 8 байт = **200 MB**
GPU: 16304 MB → проходим ✅

## Выходные таблицы (3 шт.)

### Таблица 1: **Только FFT** (hipfftExecC2C)
Чистое время FFT-вычисления

### Таблица 2: **GPU processing** (Pad + FFT)
Всё кроме Upload/Download

### Таблица 3: **Полный цикл** (Upload + Pad + FFT + Download)
CPU → GPU → CPU

## Контрольная точка

- 320×1024 запускается В НАЧАЛЕ и В КОНЦЕ матрицы
- Сравнение показывает drift (прогрев, троттлинг GPU)
- Те же параметры: warmup=5, runs=10

### Подход

1. Один ROCm backend на весь тест
2. Один FFTProcessorROCm (переиспользуется, внутри перестраивается)
3. **Control point START** → warmup(5) + measure(10)
4. **Матрица** 260 ячеек:
   - n_point = nfft (вход = FFT размер, без лишнего padding)
   - Warmup(5) + Measure(10) для каждой ячейки
   - Тайминги из ROCmProfEvents: Upload, Pad, FFT, Download
5. **Control point END** → warmup(5) + measure(10)
6. Экспорт в Markdown: 3 таблицы + сравнение контрольных точек

### SVM
