# DelayedFormSignalGenerator — Файл несоответствий (план vs реализация)

> **Дата**: 2026-02-11  
> **Цель**: Отражение отличий между планом (Plan_FractionalDelay_Farrow.md), задачей (TASK_DelayedFormSignalGenerator_Farrow.md) и фактической реализацией.

## 1. Терминология: Farrow vs Lagrange 48×5 — реализовано не то

| План / ТЗ | Реализация | Статус |
|-----------|------------|--------|
| **По ТЗ нужна структура Farrow**: полином по μ, схема Горнера, базисные фильтры фиксированы | Сейчас: **48 дискретных строк** матрицы: `row = (uint)(μ * 48) % 48`, 5 коэффициентов на строку (Lagrange 48×5 по строкам) | ❌ Реализован не тот алгоритм |

**Важно:** Сделано не то, что требует ТЗ. ТЗ предусматривает именно **Farrow** (вычисление в ядре по полиному от μ, схема Горнера). Текущая реализация — выборка готовой строки матрицы 48×5 по дискретному μ; это не структура Farrow.

**Что нужно:** Переделать на **настоящий Farrow** — задержка через полином по μ в ядре (базисные фильтры фиксированы, μ передаётся/вычисляется, выход по схеме Горнера). Чтобы не забыть, запись вынесена в [MemoryBank/DiscussionPlan/DelayedFormSignal_NeedFarrow.md](../DiscussionPlan/DelayedFormSignal_NeedFarrow.md).

## 2. Расположение kernel и матрицы

| План / ТЗ | Реализация | Статус |
|-----------|------------|--------|
| Матрица из файла `lagrange_matrix_48x5.json` | Матрица **встроена** в `delayed_form_signal_generator.cpp` (kBuiltinLagrangeMatrix); опционально `LoadMatrix(json_path)` | ⚠️ Отличие |
| — | Kernel **inline** в том же .cpp (FRACTIONAL_DELAY_KERNEL_SOURCE) | ⚠️ Отличие |

**Пояснение:** Встроенная матрица совпадает с [lagrange_matrix_48x5.json](../DiscussionPlan/lagrange_matrix_48x5.json). JSON поддерживается через `LoadMatrix()` для тестов и смены коэффициентов.

**Рекомендация:** Оставить как есть. При необходимости вынести kernel в отдельный .cl по аналогии с FormSignalGenerator (см. FormSignalGenerator_Разногласия.md).

## 3. Порядок шагов: задержка и шум

| План (раздел 7) | Реализация | Статус |
|-----------------|------------|--------|
| Шаг 1: сигнал по формуле → Шаг 2: задержка 48×5 → Шаг 3: шум → Шаг 4: нули вне интервала | Шаг 1: FormSignalGenerator (noise=0) → один kernel: **задержка + шум** в одном проходе; нули на границах через READ_SAMPLE | ✅ Соответствует |

**Пояснение:** Логика та же: сначала «чистый» сигнал, затем задержка и шум. В реализации задержка и шум объединены в одном kernel (меньше проходов по данным). Граничные нули реализованы через подстановку 0 при чтении за пределами [0, points).

## 10. Краткая сводка

- **Соответствует плану/ТЗ:** имя класса, модуль, тип float для delay_us/sample_rate/матрицы, выход InputData\<cl_mem\>, порядок «сигнал → задержка → шум», нули на границах, демо с графиками, передача параметров из Python, эталон 48×5 в NumPy/C++, использование матрицы из lagrange_matrix_48x5.json (или встроенный эквивалент).
- **Критичное отличие:** реализован не алгоритм Farrow по ТЗ, а Lagrange 48×5 по строкам; требуется переделка на Farrow (см. п. 1 и DiscussionPlan/DelayedFormSignal_NeedFarrow.md).
- **Прочие отличия:** (2) матрица по умолчанию встроена в код + опция LoadMatrix(JSON); (3) kernel встроен в .cpp, а не в отдельный .cl.

Файл можно обновлять по мере изменений плана или реализации.
