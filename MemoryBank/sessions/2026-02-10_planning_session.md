### 2️⃣ Ключевые исправления понимания

**ВАЖНО! Кодо изначально неправильно поняла требования:**

#### ❌ Неправильно (было):
```cpp
SpectrumMaximaFinder(const SpectrumParams& params, IBackend* backend);
std::vector<SpectrumResult> Process(const vector<complex<float>>& data);
```

#### ✅ Правильно (стало):
```cpp
// Конструктор — ТОЛЬКО backend
SpectrumMaximaFinder(IBackend* backend);

// Process — универсальный шаблонный метод
template<typename T>
std::vector<SpectrumResult> Process(
    const InputData<T>& input,           // Данные + параметры (antenna_count, n_point)
    const ProcessingParams& params,      // Параметры обработки (repeat_count, sample_rate)
    PeakSearchMode mode = ONE_PEAK       // Выбор алгоритма (1 или 2 вершины)
);
```

**Ключевая идея Alex**: Параметры (antenna_count, n_point) приходят **ВМЕСТЕ С ДАННЫМИ**, а не в конструкторе!

### 3️⃣ Про "clBuffer"

**Вопрос Alex**: "clBuffer - ЭТО есть в стандарте OpenCL?"

**Ответ Кодо** (через context7):
- ❌ НЕТ типа "clBuffer" в стандарте OpenCL!
- ✅ ЕСТЬ только `cl_mem` (handle на memory object)
- "clBuffer" — это разговорное название для `cl_mem` созданного через `clCreateBuffer()`

**Решение**: Поддерживаем `cl_mem` напрямую через `InputData<cl_mem>` → покрывает все случаи!

### 4️⃣ Гениальная идея Alex про параметр mode

**Идея**: Параметр `mode` в `Process()` управляет алгоритмом (1 или 2 вершины)!

```cpp
enum class PeakSearchMode {
    ONE_PEAK,   // → GetPostKernelSource_OnePeak() → 4 MaxValue
    TWO_PEAKS   // → GetPostKernelSource_TwoPeaks() → 8 MaxValue
};

// Использование:
finder.Process(input, params, PeakSearchMode::ONE_PEAK);
finder.Process(input, params, PeakSearchMode::TWO_PEAKS);
```

**Это супер!** Динамический выбор алгоритма БЕЗ разных методов! 💡
